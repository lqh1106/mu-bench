# Tool contract boundaries patch

These boundary corrections originated under T-R3/JT5 and are retained by T-R4/JT6. The original correction identifier is tool-contract-boundaries-r1. It does not change the SUT conversation scheduler.

Playlist and whole-album scope spellings use public finite equivalents shared by the interface, execution normalization and deterministic comparisons. Album/content identities remain strict. Router deferral reason is free prose whose substantive truth is checked in the semantic goal completion; a hidden reason code is not an additional goal.

The payer/traveler cancellation refusal needs no unrelated booking lookup. Actual facts about unseen booking records and other data-consuming scenarios still need an available source. This is a case-specific query-dependency correction, not a global exemption.

Audio evidence whose ASR interval spans an actual successful tool-result boundary is split from the original played assistant channel at that boundary and re-transcribed, with clips, hashes and the original turns retained. These are bounded audio segments, not invented word timestamps. Earlier actual result sources remain available. A verdict explicitly based only on unresolved ordering is retained as needs_audio_alignment, never converted to model failure; proven early false claims still fail. Primary, independent and conflict reviews receive the same prepared evidence.

Complete historical episodes can be re-evaluated with an evaluation-only corrected case and actual preserved audio. Never overwrite the delivered case, tool results or original formal scores. Schema changes are not claimed to have been delivered historically. This correction does not fix wrong album names, wrong business values, requester errors or other unapproved case issues.


## Request revisions and terminal checks

- A valid replacement request may supersede an earlier request. Saying that the old request is obsolete or overridden can communicate its non-execution; no special refusal phrase is required.
- A lookup is required when the task consumes unavailable service facts. Directly supplied preferences and the actual successful write result can support the authored answer without an unrelated preliminary read.
- Mandatory accessibility and soft distance preferences are separate. An affected attendee may explicitly withdraw their own distance preference. The request-basis review must support that actual prior owner request before the evaluator resolves the expected soft-preference field. Submitted arguments alone never define the oracle, and other participants' scope remains unchanged.
- Event times use local 24-hour HH:MM and the supplied daypart. Explicit AM/PM is normalized; bare 06:00 and 18:00 are different. The evening-event fixture provides its daypart before the dialogue.
- Diagnostic return pairs are applicable only when their return event was actually delivered. Absent returns remain in the audit with null outcomes and are omitted from metric denominators. Missing original goals remain failures.
- A clear owner-bound reference by public participant ID can satisfy a return anchor without a vocative. An unrelated mention of an ID cannot.


### Conditional obligations, spoken dates, and provisional reviews

A conditional obligation is not an unconditionally required outcome. After all authored events are delivered, evidence-validated non-applicability is carried through machine aggregation. Missing mandatory events do not qualify. Spoken calendar dates are compared by unambiguous calendar meaning; ASR separator changes alone do not change the date. Original quotations remain unchanged. The chore-workload scene requires reading and discussing the provisional proposal; it does not require an unrequested workload write or a final allocation. Legitimate optional workload notes may preserve the stated constraint without finalizing the proposal.
